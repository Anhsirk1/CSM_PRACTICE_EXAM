14. Question
Name a security benefit gained from using scoped applications:

Prevents third party integrations
Prevents changes to tables without explicit permission from IT
Limits accessibility to other applications in the instance
Limits the number of update sets that can be applied
 Unattempted
C. Limits accessibility to other applications in the instance (Correct)

The primary purpose of a scoped application is to isolate its data and artifacts from other applications on the platform. By default, an application scope blocks other scoped applications or the global scope from accessing its tables, scripts, and configurations unless explicit cross-scope access is granted via Application Access settings. This prevents unauthorized applications from reading, modifying, or deleting sensitive CSM data (like customer accounts, contacts, or cases).

A. Prevents third party integrations (Incorrect)

Scoped applications do not prevent third-party integrations; in fact, they fully support them. You can easily build REST/SOAP integrations, utilize IntegrationHub spokes, or expose scripted REST APIs within a scoped application to connect CSM with external CRM or billing systems. Scoping simply controls internal access between applications residing on the same instance.

B. Prevents changes to tables without explicit permission from IT (Incorrect)

Application scoping enforces programmatic access and architectural boundaries at the system level, not human workflows or IT approval gates. While it restricts scripts in other scopes from altering the application’s tables, it does not manage or enforce internal administrative change management processes or formal IT approvals.

D. Limits the number of update sets that can be applied (Incorrect)

There is no platform limitation on the number of update sets you can create, retrieve, or commit based on whether an application is scoped or global. Application scoping changes how changes are packaged (often using Application Repository or source control integrations like Git instead of traditional update sets), but it does not impose a numeric limit on deployment files.

46. Question
A consumer service agent receives and accepts a case which was created by a consumer. The agent needs and requests more information from the consumer. New > Open > Work in Progress > Solution Proposed > Closed
New > Open > Awaiting Info > Open > Resolved > Closed
New > Work in Progress > On Hold > Work in Progress > Resolved > Closed
Open > Pending > Work in Progress > Resolved > Closed
 Unattempted
B. New > Open > Awaiting Info > Open > Resolved > Closed

This is the correct chronological order of case states for the given scenario.

New: The case is initially created by the consumer.
Open: The agent accepts the case and begins working on it.
Awaiting Info: When the agent needs more information from the consumer, the case is put on hold.
Open: Once the agent receives the necessary information, the case is reopened to continue processing.
Resolved: The agent proposes a solution, and the consumer accepts it.
Closed: The case is successfully closed after the solution is implemented.
